## The month in one sentence

In September, I got the rebuilt Cybernetks website live and moved Operator past the Apple Developer enrolment hurdle. I did not reach the month's main goal of submitting Operator for App Store review.

## Last month's bet

- **Intended outcome:** Submit Operator for App Store review.
- **Result:** Partial. I applied for the Apple Developer Program and received confirmation that I could continue the enrolment, but I did not submit the app for review.
- **What moved:** I advanced the Apple release setup, rebuilt and launched the Cybernetks website, simplified the publishing model, and aligned the studio's branding and voice across its platforms.
- **What this changes:** The website is now ready to support future releases, so the main focus can return to completing Operator's release path.

## Business movement

- **Public product releases: None.** Operator is still not publicly available.
- **Real-use evidence: None.** I have no recorded downloads, purchases, reviews, or direct user feedback yet.
- **Public updates (1): August Monthly Snapshot.** I published the first snapshot using the more reflective format.
- **Studio platform: Rebuilt and live.** I launched the new Cybernetks website and aligned the surrounding channels with its visual style and voice.
- **Commercial progress: Apple release access moved forward.** I applied for the Apple Developer Program and can continue the organisation enrolment.
- **Financial result: -€98.99.** There was no Cybernetks income this month. The €98.99 expense was the annual Apple Developer Program fee.

## Projects in motion

### Operator

- **Stage at the start:** The launch functionality was built, but the signed Apple release path was incomplete.
- **Stage now:** The Apple Developer Program application has moved forward, but Operator has not been submitted for review or released publicly.
- **Next gate:** Finish the organisation setup and remaining release work, then submit the app for App Store review.

### Cybernetks website

- **Stage at the start:** The existing site and content workflow no longer matched how I wanted to present the studio or publish updates.
- **Stage now:** The rebuilt site is live, the publishing model is simpler, and the studio branding and voice are aligned across platforms.
- **Next gate:** Use the website-first workflow for the next Log without making a podcast or video a requirement.

## What September revealed

September produced meaningful studio infrastructure, but not the product outcome I had chosen. The new website and publishing system make Cybernetks easier to present and maintain, yet Operator still did not cross the App Store submission gate. That distinction matters: enabling work supports a release, but it does not replace one.

The Apple Developer application also showed how an unclear administrative step can remain a blocker for longer than the work itself. Once I completed the application, the hurdle felt smaller. The useful response is to keep turning the remaining release process into concrete steps instead of letting it stay as one large, vague task.

## What comes next

For October, the primary outcome remains submitting Operator for App Store review. I will keep new feature work on hold and treat the rebuilt website as support for the release rather than a new stream of work.

- **Done when:** I have completed the organisation and release setup, validated the release candidate on my supported devices, finished the App Store listing, and submitted the build to Apple.
- **First concrete step:** Finish setting the organisation name and complete the remaining Apple Developer enrolment forms.
